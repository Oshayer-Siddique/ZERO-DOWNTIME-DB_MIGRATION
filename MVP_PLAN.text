1. What is this project actually doing? (Simple explanation)

Imagine you have an application running in production.

Current database:

users table

id | full_name
--------------
1  | John Smith
2  | Alice Brown

Your developers want to improve the design:

New database:

users table

id | first_name | last_name
---------------------------
1  | John       | Smith
2  | Alice      | Brown

A normal developer might do:

ALTER TABLE users DROP COLUMN full_name;
ALTER TABLE users ADD first_name;
ALTER TABLE users ADD last_name;

Problem:

During deployment:

Old Application
        |
        |
        v
 expects full_name


Database migration happens


Database
        |
        |
        v
 full_name removed


Old application crashes

Users see:

500 Internal Server Error

Your project solves this using:

Expand → Migrate → Contract pattern
Phase 1: Expand

Add new structure but keep old one.

Database:

users

id | full_name | first_name | last_name
---------------------------------------
1  | John Smith| NULL       | NULL

Old app works.

New app can start using new columns.

Phase 2: Dual Write + Backfill

Synchronize data.

Example:

New user created:

first_name = John
last_name = Smith

Trigger copies:

full_name = John Smith

Now both versions work.

Phase 3: Contract

After old application is completely removed:

Remove old column:

users

id | first_name | last_name
---------------------------
1  | John       | Smith

No downtime.
